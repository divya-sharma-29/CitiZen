# CitiZen Database Design

## Database

**PostgreSQL**

---

# Purpose

The database stores all information required for the CitiZen platform, including users, civic issue reports, AI analysis, comments, notifications, and community interactions.

It is designed to be scalable, secure, and maintainable as the application grows.

---

# User Roles

- Citizen
- Officer
- Worker
- Admin

1. Users

# Table: Users

Stores information about every registered user.

| Column | Type | Description |
|---------|------|-------------|
| id | UUID / INT | Unique user ID |
| full_name | VARCHAR(100) | Full name |
| email | VARCHAR(255) | Unique email address |
| password_hash | VARCHAR(255) | Encrypted password |
| phone | VARCHAR(20) | Contact number |
| role | ENUM | Citizen, Officer, Worker, Admin |
| profile_picture | TEXT | Profile image URL |
| trust_score | INTEGER | Reputation score (Default: 0) |
| created_at | TIMESTAMP | Account creation time |
| updated_at | TIMESTAMP | Last profile update |

---

# Table: Categories

Stores all supported civic issue categories.

| Column | Type | Description |
|---------|------|-------------|
| id | UUID / INT | Category ID |
| name | VARCHAR(100) | Category name |
| icon | TEXT | Icon representing the category |
| description | TEXT | Category description |

### Example Categories

- Pothole
- Garbage
- Water Leakage
- Broken Streetlight
- Open Manhole
- Fallen Tree
- Damaged Footpath
- Illegal Dumping

---

# Table: Reports

Stores every civic issue reported by citizens.

| Column | Type | Description |
|---------|------|-------------|
| id | UUID / INT | Report ID |
| user_id | FK | User who reported the issue |
| category_id | FK | Issue category |
| title | VARCHAR(200) | Short title |
| description | TEXT | Description written by the citizen |
| ai_description | TEXT | Description generated by AI |
| ai_category | VARCHAR(100) | AI predicted category |
| ai_confidence | DECIMAL(5,2) | AI confidence percentage |
| latitude | DECIMAL(10,8) | GPS Latitude |
| longitude | DECIMAL(11,8) | GPS Longitude |
| address | TEXT | Full location address |
| severity | ENUM | Low, Medium, High |
| priority_score | INTEGER | AI calculated priority score |
| status | ENUM | Pending, Verified, In Progress, Resolved |
| is_anonymous | BOOLEAN | Whether the reporter chooses to stay anonymous |
| created_at | TIMESTAMP | Report creation time |
| updated_at | TIMESTAMP | Last modification time |
| resolved_at | TIMESTAMP | Resolution time |

---

# Table: ReportImages

Stores images uploaded with reports.

| Column | Type | Description |
|---------|------|-------------|
| id | UUID / INT | Image ID |
| report_id | FK | Related report |
| image_url | TEXT | Image storage URL |
| uploaded_at | TIMESTAMP | Upload timestamp |

---

# Table: Comments

Allows citizens and authorities to communicate on a report.

| Column | Type | Description |
|---------|------|-------------|
| id | UUID / INT | Comment ID |
| report_id | FK | Related report |
| user_id | FK | Comment author |
| message | TEXT | Comment content |
| created_at | TIMESTAMP | Comment creation time |

---

# Table: Appreciations

Stores appreciation messages sent by citizens to workers after an issue has been resolved.

| Column | Type | Description |
|---------|------|-------------|
| id | UUID / INT | Appreciation ID |
| worker_id | FK | Worker receiving appreciation |
| citizen_id | FK | Citizen sending appreciation |
| report_id | FK | Related report |
| message | TEXT | Appreciation message |
| created_at | TIMESTAMP | Creation time |

### Example

> "Thank you for repairing the road so quickly. The area feels much safer now."

---

# Table: Notifications

Stores notifications sent to users.

| Column | Type | Description |
|---------|------|-------------|
| id | UUID / INT | Notification ID |
| user_id | FK | Recipient |
| title | VARCHAR(255) | Notification title |
| message | TEXT | Notification message |
| is_read | BOOLEAN | Notification read status |
| created_at | TIMESTAMP | Notification creation time |

### Example Notifications

- Your report has been verified.
- Your report has been assigned to a worker.
- Your report has been resolved.
- A nearby issue requires community verification.

---

# Entity Relationships

- One User can create many Reports.
- One Report belongs to one User.
- One Category can have many Reports.
- One Report can have multiple Images.
- One Report can have multiple Comments.
- One User can write multiple Comments.
- One Worker can receive multiple Appreciations.
- One Citizen can send multiple Appreciations.
- One User can receive multiple Notifications.

# Future Database Enhancements

The following tables can be introduced in future versions of CitiZen:

## CommunityVerification

Stores verification votes from nearby citizens.

## Votes

Stores community upvotes for important issues.

## WorkerAssignments

Tracks which worker has been assigned to which issue.

## StatusHistory

Maintains a timeline of every status change made to a report.

## LocalityStatistics

Stores aggregated statistics for each locality to power AI heatmaps and analytics.

## AIAnalysisLogs

Stores AI predictions, confidence scores, and processing history.

## AuditLogs

Tracks important system activities for security and transparency.

---

# Database Design Principles

- Normalize data to reduce duplication.
- Store passwords securely using hashing.
- Use foreign keys to maintain relationships.
- Keep the database scalable for future features.
- Record timestamps for auditing and analytics.
- Design tables that support AI-powered insights and real-time updates.
